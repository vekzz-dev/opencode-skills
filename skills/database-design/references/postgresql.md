# PostgreSQL Reference

## Unique Features

- **Arrays**: `TEXT[]`, `INTEGER[]` — native array type, indexable with GIN
- **JSONB**: Binary JSON with indexing (`GIN`), operators (`->`, `->>`, `@>`, `?`)
- **Range types**: `TSRANGE`, `DATERANGE`, `INT4RANGE` — no app-level overlap checks
- **Intervals**: `INTERVAL` type for time arithmetic
- **Full-text search**: `tsvector` / `tsquery` with custom dictionaries
- **Extensions**: `postgis` (GIS), `pg_trgm` (fuzzy search), `uuid-ossp`, `pgcrypto`

## Data Types

- `SERIAL` / `BIGSERIAL` — auto-increment (legacy; prefer `IDENTITY` in PG 10+)
- `GENERATED BY DEFAULT AS IDENTITY` — standard-compliant auto-increment
- `TIMESTAMPTZ` — stores UTC, converts to session timezone on read
- `UUID` — stored as 128-bit, consider `gen_random_uuid()` for defaults
- `NUMERIC(precision, scale)` — arbitrary precision, use for money
- `BYTEA` — binary data, avoid if possible (store files elsewhere)

## Indexing

| Index Type | Use Case |
|-----------|----------|
| `BTREE` (default) | Equality, range, sorting |
| `GIN` | JSONB, arrays, full-text search, trigrams |
| `GIST` | GIS, range types, full-text (ranking) |
| `BRIN` | Large tables with naturally ordered data (logs, time-series) |
| `HASH` | Equality only, rarely useful |
| Partial indexes | `CREATE INDEX ... WHERE active = true` |
| Covering indexes | `INCLUDE (col1, col2)` — PG 11+ |
| Concurrent builds | `CREATE INDEX CONCURRENTLY` — no table lock |

## Query Features

- **CTEs**: `WITH ... AS` — materialized by default; `WITH ... AS NOT MATERIALIZED` in PG 12+
- **Window functions**: `ROW_NUMBER()`, `RANK()`, `LAG()`, `LEAD()` — over `PARTITION BY`
- **`RETURNING`**: `INSERT ... RETURNING id` — get back inserted data
- **`DISTINCT ON`**: `SELECT DISTINCT ON (col1) col1, col2` — first row per group
- **Lateral joins**: `LEFT JOIN LATERAL` — call a subquery per row
- **`ON CONFLICT`**: `INSERT ... ON CONFLICT (id) DO UPDATE SET ...` — upsert
- **`LISTEN`/`NOTIFY`**: Lightweight async event notifications

## Migration Quirks

- `ALTER TABLE ... ADD COLUMN` with `DEFAULT` no longer rewrites table (PG 11+)
- No `ALTER COLUMN ... SET DATA TYPE` if the column has a default — drop default first
- `DROP COLUMN` only marks column as dropped (does not reclaim space until `VACUUM FULL`)
- Use `pg_repack` to reclaim space without downtime

## Performance

- `EXPLAIN (ANALYZE, BUFFERS)` — the standard diagnostic
- `VACUUM` is manual/automatic — monitor `n_dead_tup` in `pg_stat_user_tables`
- Connection pooling required beyond ~200 connections (PgBouncer, pgcat)
- `work_mem` per sort/hash — too low kills complex queries, too high kills memory

## Testing

```bash
# Spin up test instance
docker run -d --name pg-test -e POSTGRES_PASSWORD=test -p 5432:5432 postgres:16

# Dump schema only
pg_dump --schema-only -h localhost mydb > schema.sql

# Restore from dump
psql -h localhost mydb < dump.sql
```
